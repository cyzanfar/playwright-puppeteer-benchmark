3600 measured records and 240 warmups. Each library and scenario has 50 measured iterations in each of 3 batches. Measured failures: 1. Warmup failures: 0. Forced cleanups: 2250 measured and 141 warmup.

Successful measured runs only. Failed runs and warmups remain in raw.jsonl and failure counts, but not timing or memory percentiles.

Sorted values; rank=(n-1)*p; linear interpolation between floor(rank) and ceil(rank). Median uses p=0.5 and p95 uses p=0.95.

KiB. Each iteration schedules aggregate RSS sampling every 50 ms for the Node driver and attributed Chrome tree, then takes the peak. Statistics summarize those per-iteration peaks. RSS counts resident pages, not unique physical memory. Shared pages can be counted in more than one process, so the sum can overstate memory. A 50 ms sampler can miss shorter spikes, and Chrome startup before root discovery is not fully sampled. The Node driver is reused across iterations while each browser is fresh.

browser.close() has 250 ms to finish. If the owned Chrome tree stalls it, the runner allows 100 ms for orphaned helpers, then signals only owned Chrome processes. SIGTERM has 250 ms before SIGKILL. Forced cleanup counts are reported.

Wall time includes the run-scoped fixture reset, process-monitor setup, browser launch, context/page creation, workflow, cleanup, and the process-exit check. It is absolute elapsed time, not a normalized score. Outliers remain in the data. Renderer recovery crashes one renderer through CDP Page.crash, not the whole browser.
